## e) WHAT WE SHOULD IMPROVE (process, from this session)

1. **Pre-tag changelog curation step** — release runbook should say: curate `[Unreleased]` INTO the release PR (push to the release branch, merge immediately) so the tag carries the curated file. This session proved release-please alone strands curated content.
2. **Run the nix gates before tagging** (`nix flake check` at minimum) — I only ran `nix run .#check`; the flake build/vendorHash path is technically unverified since the go.mod edit.
3. **Lint version single source of truth** — golangci-lint version now lives in 3 places (flake, ci.yml, release.yml). A comment cross-reference exists in AGENTS.md, but a checksum/pin check in CI would be better.
4. **Daemon hygiene** — it committed my in-flight edits under `chore: auto-commit` (swallowing two intended conventional messages), reset local master once, and pushes without coordination. Workflows changes and go.mod are exactly the files it should NOT auto-sweep.
5. **Verify links before publishing them** in release notes (the migration-guide URL).
6. **Red-master release block** — require green CI on the release PR branch (or a DontMergeMeYet-style gate keyed on master CI) so a release can't merge into a broken trunk.
